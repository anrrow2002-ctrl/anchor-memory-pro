# Anchor Memory

SillyTavern 长篇角色扮演分层记忆扩展。

## 安装

将本仓库作为第三方扩展安装，或把整个仓库目录放入 SillyTavern 的第三方扩展目录。`manifest.json` 必须位于仓库根目录。

## 记忆流程

- 每个有效 AI 回合生成一份逐楼 Godlog。
- 默认每 15 个有效 AI 回合生成 1 个分段锚点。
- 默认每累计 3 个完整分段锚点更新 1 次累计历史；累计历史不再按 AI 回合数直接截断。
- 动态召回默认关闭；100+ AI 回合长聊推荐开启。1.1.0 起采用“逐楼摘要/事件线粗导航 → 原始正文 chunk 二级精搜”，Godlog 没写进的小细节也能从 SillyTavern 原文中找回。
- 动态召回查询优先读取 `<content>...</content>` 或 `<context>...</context>` 中的正文；不存在这些标签时再读取普通消息正文。



## 1.1.2 摘要无限重跑修复

- Godlog 校验通过并保存为 `ready` 后立即形成不可回滚的提交边界。
- 隐藏状态、Codex、实体事件链、Embedding/IndexedDB 向量索引全部改为独立后处理；任何后处理失败都不会把摘要改回 `pending`，也不会再次调用摘要 API。
- 升级时自动修复 v1.1.0/v1.1.1 遗留的“正文完整但 stale/pending/failed”的 Godlog 状态。
- 后处理错误单独记录；向量失败只标记细节索引待重建。
- 修正普通后台生成时按钮误显示“正在重跑”的文案。

## 1.1.1 副API截断误判修复

- **完整内容优先于 `finish_reason=length`。** 某些 OpenAI 兼容供应商在输出正文已经完整闭合时仍会返回 `length/max_tokens`。现在插件会先执行任务级完整性校验；完整则直接接受，不再无意义扩容重试。
- **Godlog 使用真实结构判定。** `<Godlog>` 六字段齐全且 `Cond` 达到当前楼最低有效长度时，即使接口报告输出上限也直接保存；缺字段、缺闭合或内容明显不足时才重试。
- **Anchor/Merge 使用结束哨兵判定。** 输出已经包含 `<AnchorMemoryEnd/>` 时，接口即使报告 `length` 也视为完整；缺少结束标记时仍保留扩容重试和拒绝保存半截结果的保护。
- **没有取消真正的截断保护。** 第一次确实不完整时仍只扩容重试一次；第二次仍触发输出上限且完整性校验失败时才报错。

## 1.1.0 原文细节 RAG 与事件时间链

- **原文细节不再依赖摘要是否记住。** 每个 AI 回合的原始正文按约 560 Token 切成带重叠的 chunk；原文仍只保存在 SillyTavern，插件不复制第二份正文。IndexedDB 仅保存 chunk 向量、楼层/消息 key、字符起止位置和原文哈希。
- **分层检索避免高楼层暴力全表扫描。** 每楼由 chunk 向量本地计算一个楼层质心向量；每轮先由 Godlog/关键词、道具事件线、原文轻量词面命中和楼层质心定位少量候选楼，再只读取这些楼的 chunk 向量做精搜。
- **道具从“当前状态”升级为事件线。** 已追踪的重要物品会记录其在不同楼层的出现与变化来源，并保留起点、中段检查点和近期事件；像“10月8日获赠项链 → 10月9日未佩戴 → 10月12日再次拿出”可按剧情顺序注入。
- **累计历史不再鼓励递归删旧事实。** 默认 Merge 规则改为“压缩措辞而不是反复删除事实”，明确保留日期、人物、关键物品、承诺、决定和因果结果，避免长期合并只剩“关系发生变化”这类骨架。
- **修复两类静默截断。** Anchor/Merge 增加 `<AnchorMemoryEnd/>` 完整性哨兵，供应商即使错误返回 `finish_reason=stop` 也会因缺少哨兵而重试/拒绝保存；文本预算裁剪从“只留头尾、砍掉整个中间”改为分布式保留多个时间窗口。
- **召回选择预算与实际注入预算统一按 Token。** 不再先选数千 Token、最后又用 3200 字符头尾硬裁；最终只裁最后一个超预算命中，避免“面板显示命中但真正发给模型的中间内容已消失”。
- **向量是可重建索引，不是唯一记忆。** 向量保存在当前浏览器 IndexedDB；换浏览器/设备或清除站点数据后可点击“重建向量”。从旧版升级的已有聊天，启用 Embedding 后建议首次点击一次“重建向量”补齐历史原文细节索引；之后新楼会增量维护。
- **隐私说明：** 使用远程 Embedding API 时，用于生成向量的原文 chunk 会发送至用户自行配置的向量服务；向量结果保存在本地 IndexedDB，不会随 GitHub 插件发布。

## 1.0.7 副API设置状态同步修复

- 拉取副API模型成功后自动启用副API后台记忆，并同步勾选开关。
- “测试副API”只检查地址、密钥、模型是否齐全，不再要求后台记忆开关必须预先开启。
- 输入框同步逻辑同时读取“启用副API”复选框，避免移动端/WebView出现视觉状态与运行时状态不同步。
- 缺少配置时会明确指出缺少地址、密钥还是模型。

## 1.0.6 国产 OpenAI 兼容接口适配

- 自动识别并补齐常用国产平台 Base URL：火山方舟/豆包、硅基流动、DeepSeek、阿里百炼/千问、Kimi、智谱GLM、百度千帆、腾讯混元、MiniMax、阶跃星辰、百川、Gitee AI、魔搭。
- URL 可填主域名、Base URL 或完整 `/chat/completions`，发送前统一归一化，避免 SillyTavern 再拼接路径后出现 404/400。
- 副 API 请求移除固定 `temperature=0.25`，规避 Kimi K2.5/K2.6 等模型的参数限制，并减少不同厂商的采样参数兼容问题。
- 设置页实时显示识别到的平台与插件最终使用的 Base URL；副 API 错误附带平台、Base URL、模型和常见排查提示。
- 模型列表拉取失败不再清空手动模型 ID，兼容未开放标准 `/models` 的平台/账户。

## 1.0.5 楼层编号与摘要状态显示修复

- 逐楼摘要的“楼层”现在严格跟随 SillyTavern 的 `messageId/mesid`（例如酒馆 `#46`，摘要显示第 46 楼），不再额外 `+1`。
- 普通自动摘要在正文稳定/等待后台调度期间不再提前渲染“排队中”卡片；真实请求开始后才显示“生成中”。
- “已排队”只保留给手动重跑或真实自动重试等确实存在的排队任务。

## 1.0.3 摘要重试与重跑状态机修复

- 逐楼摘要遇到可恢复错误后会自动重试，默认最多 3 次，不再依赖下一条聊天事件触发。
- 同一楼增加请求锁；重复点击“重跑本楼摘要”不会创建并行模型请求。
- 正文仍在流式输出时，手动重跑会被明确记录为“已排队重跑”，正文稳定后保持 `force=true` 自动执行。
- 新楼正文流式输出期间不再提前渲染空的逐楼摘要栏；摘要真正开始、排队、自动重试和最终失败使用不同状态提示。
- 切换聊天或暂停插件时会清理摘要重试定时器与排队状态，避免旧任务跨聊天继续执行。

## 1.0.2 稳定性与高楼层修复

- 修复“完整日期 + 时段”被当作当天 00:00 导致的伪时间倒退；时段改按模糊区间比较，避免 23:30 → “深夜”之类再次误报；“一周后 / N天后 / N周后 / N个月后”会继续推进并保留日期锚点。
- 补回消息记忆徽章的工作台跳转函数，点击徽章可直接查看该楼生成前实际注入的记忆快照。
- 动态召回的关键词与向量通道改用同一份语料池；摘要失败楼层可用原文保底参与向量索引，纯关键词命中也不再被固定压在低分上限。
- 取消分段锚点与累计历史的无效 embedding，只索引真正会参与旧楼召回的逐楼摘要 / 原文保底。
- 统一旧楼显示为“第 N 个AI回合”，修复 `floor=null` 被显示成“第1楼”的边界问题。
- 去掉锚点区的二次整体裁剪，最终裁剪统一交给 Token 预算器；记忆上限超过 11,600 Token 时，各区额度会按总预算同步扩展。
- 普通摘要补写批次由最多 4 楼提升到最多 8 楼，降低快速 regenerate / 连续刷楼时锚点慢半拍的概率。
- 总览状态栏改为一句人话，后台错误独立显示；统计项统一为“等待生成摘要 / 已完成·等待锚点 / 需要修复”。
- 默认只显示常用页签，高级人物/关系/物品/提示词/摘要/场景/工具折叠到“更多功能”。
- 100+ AI 回合且未开启动态召回时，总览体检会主动提示开启。

## 1.0.1 重点调整

- Godlog 时间、地点、人物和 Cond 输出格式按当前模板收紧。
- 累计历史改为按“分段锚点数量”触发，默认 3 个分段锚点一次。
- 动态召回区分“检索条件”和“真正命中内容”，避免把最近上下文误认为已召回记忆。
- 动态召回升级为 Hybrid Retrieval：embedding 语义分与关键词/实体分同时参与融合排序，不再是“向量失败后才关键词兜底”。
- embedding 只读取自然正文（当前用户正文 + 最近正文线索），人工拆分的检索关键词只进入关键词通道，减少语义向量被 n-gram 干扰。
- 动态查询优先读取 `<content>/<context>`；缺少正文标签时会剔除 `<Think>`、`<analysis>`、`<reasoning>` 等元数据块后再读取普通正文。
- 召回面板会同时显示融合相关度、原始语义相似度和关键词分，便于判断为什么命中。
- 长聊天渲染改为近视口增量观察，并把历史 Godlog 清理限制为每个聊天上下文一次，减少 300+ 楼时的重复全量扫描。
