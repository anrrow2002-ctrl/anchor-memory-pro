# Anchor Memory · 跑团记忆整理版

版本 **1.1.4-rp.6**。

在酒馆「扩展」中使用本仓库地址安装；已有安装点击更新，再刷新酒馆页面。插件关闭自动更新，已打开的页面需要刷新后才会加载新代码。

本版修复：

- 修正 D4 把前置/末尾预设的 user、assistant 角色误当聊天楼层的问题。现在按真实聊天正文与角色有序定位，只对裁剪后实际保留的历史计深度；短聊天至少保留首条真实楼在记忆前。识别失败时安全放到请求末尾，不再退回设定区。

- 当前楼正文没有完成前，楼下不显示摘要运行/失败卡片，即使已有旧的 pending、失败或换版记录也会暂时隐藏；完成并稳定后才显示实际任务状态。
- 摘要入口在登记运行任务之前检查正文状态，等待期间不发副API、不登记假运行任务；手动重跑也等正文完成后再开始。
- 同时检查酒馆真实流式处理器；流还没结束时，临时空闲标志或提前发出的结束事件不能启动摘要。

- 「锚点记录」在聊天补全最终请求中固定使用深度 4（从实际保留的真实聊天历史往前数 4 条用户或 AI 消息，不计预设角色消息），保留末尾其他指令的顺序。rp.3 的末尾设置自动迁回 4。聊天较短或压缩后不足以安全放置时，至少留一条聊天消息在记忆之前，防止并入前置 system；工具调用与结果保持完整。记忆正文和摘要提示词保持原样。聊天补全仅在最终请求钩子里注入，避免构造阶段的副本被酒馆提前合并进其他 system；其他后端保留末尾兼容注入。
- 当前楼生成或推理时间超过 30 秒仍持续等待，不把超时当作完成；正文完成或停止后再整理。已提交消息加上酒馆明确空闲状态也能恢复漏发的结束事件。
- 当前楼仍在生成、等待稳定时，不弹「没有生成逐楼摘要」警告；同一失败的提示去重不再受正文指纹变化影响。旧历史的真实失败仍会提示。

运行检查：`npm test`（Node.js >= 18）。检查覆盖预设角色混排、短/长及裁剪后聊天、模板包裹、识别失败回退、注入前缀稳定、工具调用、旧设置迁移、慢速生成、停止/完成、缺失结束事件和警告去重。

实际缓存命中还取决于模型服务商、缓存有效期及其他提示词变化；本版避免插件更新的记忆块并入聊天前的 system 前缀。
